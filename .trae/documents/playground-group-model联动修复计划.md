# 操练场分组与模型联动修复计划

## 问题分析

当前操练场存在的问题：
1. **分组与模型不联动**：当用户在操练场选择分组时，模型列表没有相应更新
2. **可能选择不存在的模型**：用户可能选择到当前分组中不存在的模型，导致对话报错
3. **API 设计问题**：当前 `/api/user/models` 接口返回所有分组的模型并集，没有按分组过滤

## 解决方案

### 1. 前端修改
- 监听分组选择变化，当分组改变时重新加载模型列表
- 调用支持分组参数的模型接口获取对应分组的模型

### 2. 后端修改
- 修改 `/api/user/models` 接口，支持 `group` 查询参数
- 当提供 `group` 参数时，只返回该分组下的模型

## 具体任务

### [ ] 任务 1：修改后端 API 接口

- **成功标准**：
  - 当提供 `group` 参数时，返回该分组下的模型
  - 当不提供 `group` 参数时，保持原有行为（返回所有分组的模型）

  - `programmatic` TR-1.1：调用 `/api/user/models?group=default` 应返回 default 分组的模型

- **成功标准**：

- **测试要求**：
  - `human-judgement` TR-2.1：在操练场选择不同分组，模型列表应相应更新
  - `human-judgement` TR-2.2：选择分组后，模型列表只包含该分组可用的模型

### [ ] 任务 3：测试验证
- **优先级**：P1
- **描述**：测试修复后的功能，确保分组与模型联动正常工作
- **成功标准**：
  - 选择分组后，模型列表正确更新
  - 只能选择当前分组中存在的模型
  - 对话请求不再因模型不存在而报错
- **测试要求**：
  - `programmatic` TR-3.1：使用不同分组发送请求，验证请求成功
  - `human-judgement` TR-3.2：验证界面交互流畅，无明显延迟

3. **测试验证**：在前端界面测试分组与模型的联动效果

## 技术细节

### 后端修改
- 在 `GetUserModels` 函数中添加对 `group` 查询参数的处理
- 当 `group` 参数存在时，只返回该分组的模型
- 当 `group` 参数不存在时，保持原有逻辑，返回所有分组的模型

### 前端修改
- 在 `useDataLoader.js` 中添加对 `inputs.group` 的依赖
- 当 `inputs.group` 变化时，调用带有分组参数的模型接口
- 确保初始加载时使用默认分组的模型

## 预期效果

修复后，用户在操练场选择分组时，模型列表会自动更新为该分组下的可用模型，避免选择到不存在的模型导致报错。同时，保持向后兼容，确保其他功能不受影响。
