# 管理员分组显示问题修复计划

## 问题分析

**问题现象**：当管理员（RoleAdminUser 或 RoleRootUser）查看用户管理列表、使用日志列表、渠道管理列表、模型管理列表时，其他用户的分组显示为 `020045P01Y(020045P01Y)`，而不是 `laap-project(020045P01Y)`。

**根本原因**：

1. 前端 `getGroupNameBySymbol` 函数只能从 localStorage 中获取当前用户的分组映射
2. 管理员只能看到自己的分组，无法获取其他用户分组的 name 信息
3. 后端返回的用户/日志数据只包含 `group` 字段（symbol），没有 name 信息

## 实现计划

### [x] 任务 1: 后端添加获取所有用户组映射的 API
- **优先级**: P0
- **依赖**: 无
- **描述**:
  - 在 `controller/user_group.go` 中添加新的 API 端点 `/api/admin/user_groups/all`
  - 允许管理员获取所有用户组的 symbol -> name 映射
  - 保持普通用户只能获取自己的分组
- **成功标准**:
  - 管理员可以通过新 API 获取完整的用户组映射
  - 普通用户获取到的仍是自己的分组
- **测试要求**:

## 技术实现细节

### 后端 API 设计

* **端点**: `/api/admin/user_groups/all`

* **方法**: GET

* **权限**: 仅管理员

* **返回格式**:

  ```json
  {
    "success": true,
    "message": "",
    "data": {
      "020045P01Y": "laap-project",
      "020045P01Z": "test-project"
    }
  }
  ```

### 前端实现

1. **创建 UserGroupContext** 管理全局分组映射
2. **修改 renderGroup 函数** 使用全局映射
3. **更新 EditTokenModal** 保存分组映射
4. **测试所有相关组件**

## 风险评估

* **性能风险**: 分组数量较大时可能影响前端性能

* **安全风险**: 需要确保普通用户无法获取其他用户的分组信息

* **兼容性风险**: 需要确保现有功能不受影响

## 验收标准

1. 管理员可以看到所有用户的分组名称
2. 普通用户只能看到自己的分组名称
3. 所有相关页面的分组显示正确
4. 系统性能和安全性不受影响
