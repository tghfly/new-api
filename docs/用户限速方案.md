# 用户限速功能实现方案

## 需求概述
在现有按用户组限速的基础上，增加按用户限速的功能。当用户上配置了限速时，优先使用用户限速；否则回退到用户组限速。

## 优先级规则
1. **用户级别限速**（最高优先级）：如果用户的 `api_rate_total` 或 `api_rate_success` 任一字段大于0，则使用该配置
2. **用户组级别限速**（次优先级）：如果用户组配置了限速且值大于0，则使用用户组配置
3. **全局默认限速**（最低优先级）：使用系统设置中的全局默认限速配置

### ✅ 3. 设置层修改 (setting/rate_limit.go)
**新增函数**:
```go
// GetUserRateLimit 获取用户级别的限速配置
// 参数:
//   - userId: 用户ID
//   - group: 用户所属分组（用于缓存key）
// 返回值:
//   - totalCount: 总请求限速值
//   - successCount: 成功请求限速值
//   - useUserLimit: 是否使用了用户级别限速
func GetUserRateLimit(userId int, group string) (totalCount int, successCount int, useUserLimit bool) {
    // 从缓存获取用户基础信息
    userBase, err := model.GetUserCache(userId)
    if err != nil {
        // 如果缓存获取失败，尝试从数据库获取
        user, err := model.GetUserById(userId, false)
        if err != nil {
            common.SysLog(fmt.Sprintf("获取用户限速配置失败: %v", err))
            return 0, 0, false
        }
        hasLimit, total, success := user.GetUserRateLimit()
        if hasLimit {
            return total, success, true
        }
        return 0, 0, false
    }

    // 检查用户是否配置了限速
    hasLimit, total, success := userBase.GetUserRateLimit()
    if hasLimit {
        return total, success, true
    }

    return 0, 0, false
}
```

### ✅ 4. 注册限速提供者 (model/main.go)
在 `InitRateLimitProviders()` 函数中注册用户限速提供者:
```go
func InitRateLimitProviders() {
    // 注册用户组限速提供者
    setting.RegisterRateLimitProvider(setting.RateLimitProviderGroup, func(id string) (int, int, bool) {
        return setting.GetGroupRateLimit(id)
    })

    // 注册用户限速提供者
    setting.RegisterRateLimitProvider(setting.RateLimitProviderUser, func(id string) (int, int, bool) {
        userId, err := strconv.Atoi(id)
        if err != nil {
            return 0, 0, false
        }
        total, success, useUserLimit := setting.GetUserRateLimit(userId, "")
        return total, success, useUserLimit
    })
}
```

### ✅ 5. 中间件层修改 (middleware/model-rate-limit.go)
修改 `ModelRequestRateLimit` 函数，调整限速优先级逻辑:
```go
// ModelRequestRateLimit 模型请求限流中间件
func ModelRequestRateLimit() func(c *gin.Context) {
    return func(c *gin.Context) {
        // ... 原有代码 ...

        // 获取用户ID
        userId := c.GetInt("id")

        // 获取分组
        group := common.GetContextKeyString(c, constant.ContextKeyTokenGroup)
        if group == "" {
            group = common.GetContextKeyString(c, constant.ContextKeyUserGroup)
        }

        // ========== 优先检查用户级别限速 ==========
        userTotalCount, userSuccessCount, useUserLimit := setting.GetUserRateLimit(userId, group)
        if useUserLimit {
            // 使用用户级别限速
            totalMaxCount = userTotalCount
            successMaxCount = userSuccessCount
        } else {
            // 回退到用户组限速
            groupTotalCount, groupSuccessCount, found := setting.GetGroupRateLimit(group)
            if found {
                // 只有当用户组配置大于0时才覆盖，否则使用全局默认配置
                if groupTotalCount > 0 {
                    totalMaxCount = groupTotalCount
                }
                if groupSuccessCount > 0 {
                    successMaxCount = groupSuccessCount
                }
            }
        }
        // =========================================

        // 根据存储类型选择并执行限流处理器
        if common.RedisEnabled {
            redisRateLimitHandler(duration, totalMaxCount, successMaxCount)(c)
        } else {
            memoryRateLimitHandler(duration, totalMaxCount, successMaxCount)(c)
        }
    }
}
```

## 限速配置示例

### 场景1: 只配置用户组限速
```
用户组 "default": api_rate_total=60, api_rate_success=30
用户A: api_rate_total=0, api_rate_success=0
结果: 用户A使用用户组限速 (60, 30)
```

### 场景2: 配置用户级别限速
```
用户组 "default": api_rate_total=60, api_rate_success=30
用户B: api_rate_total=120, api_rate_success=60
结果: 用户B使用用户级别限速 (120, 60)，忽略用户组配置
```

### 场景3: 混合配置
```
用户组 "vip": api_rate_total=200, api_rate_success=100
用户C: api_rate_total=0, api_rate_success=150
结果: 
  - 总请求限速: 使用用户组配置 200 (因为用户total为0)
  - 成功请求限速: 使用用户级别配置 150 (因为用户success>0)
```

## 注意事项
1. 用户限速字段值为0时表示"未配置"，将回退到用户组限速
2. 只有管理员可以修改用户限速配置
3. 修改限速配置后即时生效（无需重启服务）
4. 限速计数基于Redis或内存，确保Redis配置正确以获得最佳性能
