### 2. 向量模型（/v1/embeddings）
- 在 EmbeddingHelper 函数中，将 input 字段序列化为 JSON 并存储到上下文中
```go
	// 记录输入的文本字段
	if embeddingReq.Input != nil {
		inputJson, err := common.Marshal(embeddingReq.Input)
		if err == nil {
			c.Set("input_messages", string(inputJson))
		}
	}
```
- 由于向量模型的输出通常是嵌入向量，**暂不记录输出!!!**

### 3. 重排模型（/v1/rerank）
- 在 RerankHelper 函数中，将 query 和 documents 字段序列化为 JSON 并存储到上下文中
```go
	// 记录输入的查询和文档字段
	rerankInput := map[string]interface{}{
		"query":     rerankReq.Query,
		"documents": rerankReq.Documents,
	}
	inputJson, err := common.Marshal(rerankInput)
	if err == nil {
		c.Set("input_messages", string(inputJson))
	}
```
- 在 common_handler/RerankHandler 函数中，记录 results 字段
```go
	// 记录输出的结果字段
	resultsJson, err := common.Marshal(jinaResp.Results)
	if err == nil {
		c.Set("output_message", string(resultsJson))
	}
```

### 4. VL模型（/v1/images/generations）
- 在 ImageHelper 函数中，记录 prompt 字段
```go
	// 记录输入的提示字段
	if imageReq.Prompt != "" {
		c.Set("input_messages", imageReq.Prompt)
	}
```
- 由于 VL模型的输出通常是图像 URL，**暂不记录输出!!!**

### 5. 日志存储
- 在 postConsumeQuota 函数中，将上下文中存储的输入和输出字段添加到 other 字段中，然后通过 model.RecordConsumeLog 函数存储到数据库中
```go
	// 记录输入的 messages 字段
	if inputMessages, exists := ctx.Get("input_messages"); exists {
		other["input_messages"] = inputMessages
	}
	// 记录输出的 id 和 message 字段
	if outputId, exists := ctx.Get("output_id"); exists {
		other["output_id"] = outputId
	}
	if outputMessage, exists := ctx.Get("output_message"); exists {
		other["output_message"] = outputMessage
	}
```
## 技术实现细节
1. 输入记录 ：
    - 对于文本模型，使用 common.Marshal 序列化 messages 字段
    - 对于向量模型，使用 common.Marshal 序列化 input 字段
    - 对于重排模型，使用 common.Marshal 序列化 query 和 documents 字段
    - 对于 VL模型，直接存储 prompt 字段
2. 输出记录 ：
    - 对于文本模型，使用 common.Marshal 序列化 message 字段，并记录 id 字段
    - 对于重排模型，使用 common.Marshal 序列化 results 字段
    - 对于向量模型和 VL模型，暂未记录详细输出，可根据需要扩展
3. 日志存储 ：
    - 使用现有的 model.RecordConsumeLog 函数，将输入和输出字段存储到 other 字段中
    - 保持与现有日志格式的兼容性

## 预期效果
- 能够在日志中看到用户输入的 prompt 和模型的输出
- 能够适配不同类型的模型，包括文本、VL模型、向量模型和重排模型
- 日志记录不会影响系统性能和稳定性
## 注意事项
- 日志记录可能会增加数据库存储压力，建议根据实际情况调整日志保留策略
- 对于大型请求和响应，可能会导致日志过大，建议设置合理的日志大小限制
- 对于敏感信息，建议在记录前进行适当的脱敏处理
  通过以上实现方案，我们可以对 new-api 的使用日志进行改造，记录用户的输入 prompt 以及模型的输出，同时适配不同类型的模型。
